3. การประเมินและคัดเลือก Local LLM (ขนาดเล็กกว่า 4B)
ตารางประเมิน 5 โมเดลบน GPU

การทดสอบบน GPU เครื่องเดียวกันเพื่อคัดเลือกโมเดลที่สามารถ Deploy แบบ On-Premise ได้จริง โดยพิจารณาความเร็วในการตอบ (Throughput), อัตราการใช้ VRAM, คุณภาพการเรียบเรียงภาษาไทย, และความเสี่ยงในการหลอนข้อมูล

4. สถาปัตยกรรม Universal Multi-Dimensional Anti-Hallucination Guardrail
ตารางทดสอบผลจริง 4 มิติ

การนำเสนอนวัตกรรมทางวิศวกรรมแบบ Dual-Layer เพื่อควบคุมโมเดลขนาด 3B ให้ตอบเฉพาะข้อมูลที่มีอยู่ใน Context และ Knowledge Graph อย่างเคร่งครัด 100%

มิติที่ควบคุม คำถามทดสอบ ผลลัพธ์ของโมเดลปกติ (ก่อนคุม) ผลลัพธ์หลังผ่าน Guardrail Engine กลไกตรวจสอบ
1. เบอร์โทรศัพท์ "ขอเบอร์โทรศัพท์ติดต่อของบ้านนครในหน่อยครับ" 074-321-456 (หลอนตัวเลขขึ้นมาเอง) "ขออภัยครับ ในฐานข้อมูลยังไม่มีการระบุเบอร์โทรศัพท์ติดต่อของสถานที่ดังกล่าว" Regex Grounding
2. เวลาเปิด-ปิด "โรงสีแดง หับ โห้ หิ้น เปิดทำการกี่โมงถึงกี่โมง" 08:30 - 17:00 น. (เดาเวลามาตรฐานทั่วไป) "ขออภัยครับ ในฐานข้อมูลยังไม่ได้ระบุเวลาเปิด-ปิดที่แน่นอน แนะนำตรวจสอบกับทางสถานที่โดยตรงครับ" Time Format Check
3. ราคา / ค่าเข้าชม "บ้านนครใน ค่าเข้าชมกี่บาท" ผู้ใหญ่ 50 บาท เด็ก 20 บาท (กุราคาขึ้นมา) "ขออภัยครับ ในฐานข้อมูลยังไม่ได้ระบุราคาหรือค่าเข้าชมที่แน่ชัด แนะนำสอบถามหน้าร้านครับ" Price Token Grounding
4. ตำแหน่งถนน "ร้านแต้เฮี้ยงอิ๋ว ตั้งอยู่ถนนสายใด" ถนนนครนอก ริมทะเลสาบ (สับสนชื่อถนน) "ร้านแต้เฮี้ยงอิ๋ว ตั้งอยู่บน ถนนนางงาม..." (ดึงกลับมาถูกต้อง) Graph Topology
ภาพที่ 5: แผนภาพการทำงานและการดักจับของ Universal Multi-Dimensional Guardrail Engine
🗣️ สรุปบทพูดสเตปที่ 4 (ประโยคปิดจบที่น่าประทับใจ):
"เราไม่ได้ปล่อยให้โมเดล 3B ตอบโดยไม่มีการควบคุมครับ เพราะธรรมชาติของมันจะเสกตัวเลขเมื่อเจอคำถามปลายเปิด ผมจึงสร้าง Dual-Layer Guardrail ขึ้นมา โดยมีชั้นที่สองเป็น Deterministic Verifier ตรวจสอบความถูกต้องของตัวเลขและเชื่อมโยงกับ Knowledge Graph โดยตรง หากไม่มีข้อมูล ระบบจะตัดทิ้งทันที และหากสับสนเรื่องถนน กราฟจะดึงกลับมาเป็นถนนที่ถูกต้อง ทำให้คำตอบที่ส่งไปถึงนักท่องเที่ยวผ่าน LINE ปลอดภัยจากข้อมูลเท็จ 100% ครับ"
